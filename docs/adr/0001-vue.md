# The web app moves to Vue 3, with Vue Router in history mode and Pinia

The maintainer chose Vue 3 (`<script setup>`, TypeScript) over staying on React because it is the framework they know better, and the person who maintains the app should be fluent in what it is written in; it is also somewhat lighter (about 34 kB gzipped against 45 kB). Navigation moves out of the match store into Vue Router, and zustand is replaced by Pinia. Discussion: issue #12.

## Consequences

- `packages/core`, the vision code that does not touch a framework, storage, pairing, the caller and i18n carry over unchanged. Logic that is framework-free is extracted on the React app first (starting with the board watcher, see CONTEXT.md), so the port only rewrites views.
- The router uses history mode (`createWebHistory(import.meta.env.BASE_URL)`), not hash mode: `#/` addresses look wrong and get in the way of indexing. GitHub Pages has no SPA fallback, so the build writes a copy of `index.html` into each static route's folder, and `404.html` covers routes with an id (`review/:id`, `history/:id`), which show on-device data and are never indexed. Old `#/…` links are replaced by their paths on load.
- Vite's `base` becomes absolute (`/treblewise/` on Pages, from an env variable), since a relative `./` breaks under two-segment paths.
